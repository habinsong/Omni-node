# Omni-node 노트북 / 이어보기

업데이트 기준: 2026-05-07

이 문서는 현재 코드 기준의 `노트북` 탭, notebook 저장소, 이어보기 문서 생성 흐름을 정리합니다.

## 1. 현재 범위

노트북은 설정 탭 하위 패널이 아니라 좌측 루트 메뉴의 독립 탭입니다.

지원 범위:

- 프로젝트별 `learnings.md`, `decisions.md`, `verification.md`, `handoff.md` 영속 저장
- 대시보드 `노트북` 탭에서 기록 작성, 빠른 기록, 현재 상태, 다음 액션, 문서 보기 제공
- 웹 슬래시 명령과 텔레그램 명령
- WebSocket `notebook_get`, `notebook_append`, `handoff_create`
- plan, task graph, doctor, refactor 결과를 notebook 초안으로 옮기는 빠른 기록 버튼

핵심 원칙:

- 비워 둔 `projectKey`는 현재 프로젝트 루트 기준으로 자동 계산됩니다.
- append는 markdown 문서에 `## <Kind> · <timestamp>` 블록으로 누적됩니다.
- 이어보기 문서는 작업 메모, 방향 정리, 확인한 내용 미리보기를 모아 `handoff.md`를 다시 생성합니다.
- notebook append와 이어보기 생성은 현재 LLM을 쓰지 않고 규칙 기반으로 동작합니다.
- UI는 사람이 쓰는 말로 보여주고, 내부 저장 파일명만 `learnings.md`, `decisions.md`, `verification.md`, `handoff.md`를 유지합니다.

## 2. 저장 경로

기본 상태 루트는 `~/.omninode`입니다.

```text
~/.omninode/notebooks/<project-key>/learnings.md
~/.omninode/notebooks/<project-key>/decisions.md
~/.omninode/notebooks/<project-key>/verification.md
~/.omninode/notebooks/<project-key>/handoff.md
```

정리 기준:

- 이 경로는 재생성 캐시가 아니라 세션 간 이어보기 원본입니다.
- 다음 세션이 현재 작업을 이어받아야 하면 삭제하면 안 됩니다.
- 상태 파일은 `workspace/`가 아니라 `~/.omninode/notebooks/` 아래에 남습니다.

## 3. 대시보드 사용 흐름

### 3.1 상단 요약

노트북 탭 상단은 현재 문서 상태를 빠르게 보여줍니다.

- `남긴 문서`: 작업 메모, 방향 정리, 확인한 내용, 이어보기 중 채워진 문서 수
- `현재 작성 대상`: 지금 선택한 기록 종류
- `초안 길이`: 현재 입력된 본문 길이
- `작성 방식`: 직접 작성. 이어보기 생성은 현재 LLM 미사용, 규칙 기반

### 3.2 기록 작성

기록 작성 영역에서 아래를 한 번에 조정합니다.

- `프로젝트 키`: 직접 입력하거나 현재 프로젝트 키 사용
- `저장 루트`: 현재 notebook 저장 위치 확인
- `작업 메모`: 오늘 남길 것, 다음에 써먹을 것, 주의할 점
- `방향 정리`: 뭐 하기로 했는지, 왜 그렇게 갔는지, 일단 안 한 것
- `확인한 내용`: 직접 눌러봤거나 실행해서 본 것과 아직 찝찝한 점

본문 입력 영역은 여러 줄 기록을 전제로 크게 잡혀 있습니다. 형식 맞추기보다 다음 사람이 바로 읽고 이어갈 수 있는 말을 남기는 것이 목적입니다.

### 3.3 빠른 기록

빠른 기록은 다른 화면에서 생긴 결과를 노트북 초안으로 옮기는 기능입니다.

- `선택한 계획 가져오기`
- `그래프 결과 가져오기`
- `진단 결과 가져오기`
- `리팩터 결과 가져오기`

버튼은 바로 저장하지 않고 초안에 넣습니다. 내용을 사람이 확인한 뒤 저장하는 흐름입니다.

### 3.4 현재 상태와 다음 액션

우측 영역은 현재 notebook 상태를 보여주고 다음에 채울 항목을 제안합니다.

- project key와 저장 루트
- 최근 동기화 시점
- 이어보기 생성 방식
- 작업 방향이 비어 있는지
- 확인한 내용이 비어 있는지
- 재사용할 교훈이 없는지
- 이어보기 문서가 아직 없는지

`다음 액션` 영역은 빠른 기록 영역과 시각적으로 같은 하단 높이를 유지하도록 배치되어, 넓은 화면에서도 좌우 길이가 어긋나지 않게 구성됩니다.

### 3.5 문서 보기

문서 보기는 네 문서를 카드로 분리합니다.

- `작업 메모`
- `방향 정리`
- `확인한 내용`
- `다음에 이어볼 것`

넓은 화면에서는 2열 구조로 배치되고, 좁은 화면에서는 1열로 내려갑니다. 이어보기 문서는 확인한 내용 오른쪽에 위치하는 것이 기준이며, 화면 폭이 부족할 때만 아래로 이동합니다.

## 4. 명령 사용

웹 명령창과 텔레그램에서 공통으로 사용할 수 있습니다.

```text
/notebook show [project-key]
/notebook append <learning|decision|verification> <내용>
/handoff [project-key]
```

예시:

```text
/notebook show
/notebook append decision 이번 작업은 plan_run에서 task graph로 넘기는 방향으로 정리했다
/notebook append verification doctor에서 fail 항목이 없는 것을 확인했다
/handoff
```

텔레그램에서는 slash 없이도 아래처럼 요청할 수 있습니다.

```text
노트북 보여줘
확인한 내용에 doctor 경고 없음 추가해
이어보기 만들어줘
```

## 5. 바로 쓰는 문장

### 5.1 작업 메모

```text
오늘 남길 것:
- 자동화/계획 탭에서 계획과 그래프를 한 화면에 몰아넣으면 다시 복잡해진다.

다음에 써먹을 것:
- 큰 화면에서도 내부 좌측 선택으로 먼저 쪼개고, 보조 라우팅은 접어둔다.

주의할 점:
- 버튼과 선택창은 같은 줄 기준선에 맞춘다.
```

### 5.2 방향 정리

```text
뭐 하기로 했나:
- 노트북 탭은 사람이 직접 쓰는 메모장처럼 보이게 한다.

왜 그렇게 갔나:
- 내부 데이터 모델 용어는 사용자가 매일 쓰는 말이 아니다.

일단 안 한 것:
- 내부 저장 파일명은 바꾸지 않는다. 기존 데이터 호환이 더 중요하다.
```

### 5.3 확인한 내용

```text
확인한 것:
- 노트북 탭에서 작업 메모/방향 정리/확인한 내용 버튼이 보인다.

어떻게 확인했나:
- 브라우저에서 노트북 탭을 열고 각 버튼을 눌러봤다.

결과:
- 버튼과 입력창이 같은 줄에서 어긋나지 않는다.

아직 찝찝한 것:
- 모바일 화면에서 문서 카드 순서도 한 번 더 봐야 한다.
```

## 6. 권장 운영 루틴

1. 작업 도중 떠오른 말은 `작업 메모`
2. 방향이 바뀌었으면 `방향 정리`
3. 실제로 본 결과는 `확인한 내용`
4. 세션 종료 직전 `이어보기 만들기`

이어보기를 만들기 전에 최소 아래 세 줄은 채우는 편이 안전합니다.

1. 이번 작업 방향 1개 이상
2. 실제로 확인한 내용 1개 이상
3. 다음 세션이 바로 이어받을 수 있는 next action 한 줄

## 7. 확인 포인트

사용자가 직접 확인할 때는 아래만 보면 됩니다.

1. 노트북 탭에서 작업 메모 저장
2. 방향 정리 또는 확인한 내용 저장
3. 빠른 기록 초안 생성
4. 이어보기 생성
5. `~/.omninode/notebooks/<project-key>/` 아래 네 문서 갱신 확인
