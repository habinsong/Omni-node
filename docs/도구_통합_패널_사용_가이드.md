# 도구 통합 패널 사용 가이드

업데이트 기준: 2026-05-07

도구 통합 패널은 설정 탭의 `고급 도구` 안에서 provider/tool/rag 실행 상태를 관측하고 필요한 제어 요청을 보내는 운영 패널입니다.

이 패널의 목적은 “기능을 만드는 화면”이 아니라 “현재 연결 상태와 도구 호출 결과를 빠르게 확인하는 화면”입니다.

## 1. 화면 흐름

현재 패널은 아래 순서로 읽으면 됩니다.

1. `상태 요약`
2. `Provider 상태`
3. `Guard 관측`
4. `제어 요청`
5. `결과 확인`

이 순서는 문제를 좁혀 가기 위한 운영 순서입니다.

- 먼저 전체 상태를 봅니다.
- provider 키 누락이나 오류를 확인합니다.
- 검색/guard가 답변을 차단했는지 봅니다.
- 필요한 도구 요청만 실행합니다.
- 결과 테이블에서 성공/실패와 근거를 확인합니다.

## 2. 상태 요약

상태 요약은 패널 상단에서 현재 도메인별 상태를 짧게 보여줍니다.

| 영역 | 의미 |
|---|---|
| `provider` | Gemini, Groq, Cerebras, Copilot, Codex 가용 상태 |
| `tool` | sessions, cron, browser, canvas, nodes, telegram 계열 도구 상태 |
| `rag` | web, memory 검색/조회 도구 상태 |

카드는 진단용 요약입니다. 세부 원인은 아래 `Provider 상태`, `Guard 관측`, `결과 확인`에서 봅니다.

## 3. Provider 상태

Provider 상태 영역은 제공자별 준비 상태와 실패 원인을 보여줍니다.

확인할 값:

- `ready`
- `api_key_missing`
- `cli_auth_required`
- `error`
- 최근 성공/실패 건수
- 오류 reason

운영 기준:

- `api_key_missing`이면 설정 탭의 모델/사용량 또는 키 관리 영역에서 먼저 키를 저장합니다.
- Copilot/Codex가 CLI 인증을 요구하면 같은 설정 탭의 상태 조회/로그인 경로를 먼저 확인합니다.
- provider가 준비되지 않으면 routing fallback이 다음 provider로 넘어갈 수 있습니다.

## 4. Guard 관측

Guard 관측은 검색/RAG 응답이 왜 통과되거나 차단됐는지 보는 영역입니다.

대표 확인값:

- evidence coverage
- freshness
- credibility
- count-lock 충족 여부
- cache fallback 사용 여부
- guard 차단 사유

최신정보 질의가 이상하면 provider보다 먼저 guard/evidence 상태를 보는 편이 빠릅니다.

## 5. 제어 요청

제어 요청 영역에서는 아래 도메인의 요청을 직접 보낼 수 있습니다.

| 도메인 | 대표 action |
|---|---|
| `sessions` | list, history, send, spawn |
| `cron` | status, create, toggle, delete |
| `browser` | status, open, close |
| `canvas` | status, present |
| `nodes` | status, pending, invoke |
| `telegram` | command simulation |
| `web` | search, fetch |
| `memory` | search, get |

권장 사용법:

1. 요청 도메인을 고릅니다.
2. action을 고릅니다.
3. 필요한 payload만 입력합니다.
4. 실행 후 결과 확인 영역에서 응답을 봅니다.

## 6. 결과 확인

결과 확인 영역은 최근 제어 요청과 도구 호출 결과를 보여줍니다.

확인할 값:

- domain
- action
- status
- duration
- error reason
- response summary
- raw payload 요약

오류를 볼 때는 `status=error` 행만 먼저 보고, reason이 provider 문제인지 payload 문제인지 구분합니다.

## 7. Groq 모델 / 제한량 / 사용량 표

Groq 영역은 모델과 사용량을 같이 봅니다.

| 컬럼 | 의미 |
|---|---|
| `RPM` | 분당 요청 한도 |
| `RPD` | 일당 요청 한도 |
| `TPM` | 분당 토큰 한도 |
| `TPD` | 일당 토큰 한도 |
| `ASH` | 시간당 오디오 초 한도 |
| `ASD` | 일당 오디오 초 한도 |
| `사용량(분/시/일)` | 현재 윈도우 기준 누적 사용량 |
| `라이브 잔여/리셋` | 응답 헤더 기준 남은 요청/토큰과 리셋 힌트 |

사용량 집계는 분/시/일 경계에서 자동으로 기준점이 갱신됩니다. 인증 상태에서는 매 분 자동 재조회되고, 필요하면 `새로고침`으로 즉시 갱신할 수 있습니다.

## 8. 모델 적용 버튼

Groq 영역의 `모델 적용` 버튼은 전역 기본 Groq 모델 선택값을 변경합니다.

- 적용 대상: 단일/오케스트레이션/다중 모드에서 `Groq`를 선택했을 때의 기본 모델
- 영향: 이후 전송 요청에서 별도 모델을 지정하지 않으면 이 모델이 기본으로 사용됨
- 주의: 이미 실행 중인 요청의 모델은 변경되지 않음

## 9. 운영 권장 순서

1. 상태 요약에서 오류가 있는 도메인 확인
2. Provider 상태에서 키 누락 또는 CLI 인증 문제 확인
3. 검색/RAG 문제면 Guard 관측에서 차단 사유 확인
4. 제어 요청으로 필요한 도구만 실행
5. 결과 확인에서 오류 행 우선 점검
6. 필요하면 모델/사용량 영역에서 Groq 기본 모델 재선택
