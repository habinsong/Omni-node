# Omni-node 디렉터리 가이드

업데이트 기준: 2026-05-07

이 문서는 루트부터 하위 모듈까지 “어디에 무엇이 들어 있는지”를 빠르게 찾기 위한 색인입니다.

현재 canonical 레이아웃은 `apps/`, `docs/`, `workspace/`입니다. 루트의 기존 `omninode-*`, `coding`, `runtime`, 문서 파일은 하위 호환 alias입니다. macOS/Linux에서는 심볼릭 링크를 기본으로 보고, Windows에서는 Git 설정에 따라 디렉터리 alias나 symlink placeholder로 보일 수 있습니다.

## 3. 작업공간과 산출물

### 3.1 `workspace/coding/`

이 디렉터리는 제품 소스가 아니라 작업 대상 워크스페이스입니다.

주요 하위 경로:

| 경로 | 설명 |
|---|---|
| `hello_world/` | 간단한 HTML/Python 예제 |
| `recreated/` | 재생성 예제 |
| `task/` | 작업용 파일 |
| `tetris/` | 테트리스 예제 |
| `_routine_prompts/` | 루틴 생성용 프롬프트 |
| `runs/` | 코딩 탭 세 모드가 공유하는 실행별 작업 폴더. 다중 코딩은 여기 아래에 `<provider>-<model>/` 하위 폴더를 추가로 만듦 |
| `routines/` | 루틴 실행 산출물. 브라우저 에이전트는 `assets/<runTs>/` 아래에 스크린샷과 다운로드 파일을 함께 저장 |
| `venv/` | 저장소 안에 들어 있는 Python 가상환경 |

즉, `workspace/coding/`은 앱 구현이 아니라 앱이 다루는 작업 공간입니다.

### 3.2 `workspace/.runtime/`

guard 회귀, Task runtime, Safe Refactor preview 같은 임시 결과가 쌓이는 곳입니다.

예:

- `guard_retry_timeline.json`
- `gateway_health.json`
- `logic/`
- `tasks/`
- `refactor-preview/`
- `memory-index/main.sqlite*`
- 각 loop별 bundle JSON

### 3.3 `workspace/runtime/`

현재 상태 스냅샷용 소규모 디렉터리입니다.

### 3.4 위생 관점에서 보는 분류

| 경로 | 분류 | 청소 판단 |
|---|---|---|
| `workspace/coding/venv/` | 재생성 가능한 캐시 | 필요 없으면 삭제 가능 |
| `node_modules/` | 재생성 가능한 캐시 | `npm ci`로 복구 가능 |
| `apps/omninode-middleware/bin/`, `apps/omninode-middleware/obj/` | 빌드 산출물 | 삭제 가능 |
| `workspace/.runtime/` | 회귀 결과/임시 분석물 | 보관 이유가 없으면 정리 가능 |
| `workspace/runtime/` | 현재 세션 상태 스냅샷 | 세션 종료 후 필요 없으면 정리 가능 |
| `workspace/coding/runs/` | 코딩 실행 생성 파일 | 과거 결과가 필요 없을 때만 정리 |
| `workspace/coding/routines/` | 실행 결과 이력과 브라우저 에이전트 자산 | 과거 기록이나 첨부 파일이 필요 없을 때만 정리 |
| `workspace/.runtime/logic/` | 로직 그래프 실행 스냅샷과 이벤트 로그 | 과거 로직 실행 추적이 필요 없을 때만 정리 |
| `workspace/.runtime/tasks/` | task graph 실행 로그와 결과 | graph 실행 추적이 필요 없을 때만 정리 |
| `~/.omninode/*` | 영속 상태 원본 | 삭제 전에 보존 여부를 먼저 판단 |
| `~/.omninode/plans/` | 계획 원본 | 진행 중인 계획을 다시 열어야 하면 보존 |
| `~/.omninode/tasks/` | task graph 원본 | graph 상태를 다시 열어야 하면 보존 |
| `~/.omninode/notebooks/` | 노트북/handoff 원본 | 다음 세션 인수인계가 필요하면 보존 |

기본 예시 경로는 항상 `workspace/coding` 기준으로 기억하고, 루트 `coding`은 하위 호환 alias로만 봅니다.

## 7. 저장소를 볼 때의 해석 기준

이 저장소는 아래 네 층을 동시에 담고 있습니다.

1. 제품 런타임 소스
2. 운영 문서와 계획서
3. 회귀 테스트와 아티팩트
4. 실험/작업용 워크스페이스

따라서 파일 수가 많다고 해서 모두 제품 코드인 것은 아닙니다. 실제 구현 중심은 `apps/omninode-core/`, `apps/omninode-middleware/`, `apps/omninode-dashboard/`, `apps/omninode-sandbox/` 네 군데입니다.
